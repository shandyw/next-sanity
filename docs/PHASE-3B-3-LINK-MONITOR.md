# Phase 3B.3 Find link monitor

The weekly Vercel cron is configured in `vercel.json` for Sunday 06:00 UTC. Change that cron expression there if needed. Vercel invokes scheduled jobs on production deployments only. This feature is implemented locally; it has not been deployed or run against production Sanity.

Before release, set `CRON_SECRET` (a random value of at least 32 characters) and `SANITY_LINK_MONITOR_TOKEN` in Vercel's **production** environment. The latter should be a dedicated server-only Sanity token with read access to published Looks, Finds and Site Settings and update access to Find monitoring fields. Never prefix it with `NEXT_PUBLIC_`. The endpoint returns 503 if either secret is absent, and 401 for requests without the Vercel Bearer secret. Confirm the Sanity token's least-privilege capabilities before enabling the cron.

The job reads published Looks with a publication date in the past, deduplicates their Find references, and checks only published Finds. It does not fetch Amazon URLs, follow short links, scrape pages, generate clicks, or infer stock availability. Checks cover HTTPS Amazon.com product URL shape, allowed affiliate URL format, the configured Associate tag when Associates is active, and ASIN consistency. A verified `amzn.to` link with an ASIN remains **Unchecked** because its destination and tag cannot be inspected without following it. A Find missing an affiliate URL while Associates is active is flagged for review; the public ordinary-link fallback remains available.

The cron writes only `linkStatus`, `linkCheckResult`, and `linkLastCheckedAt` on a published Find. It skips manually **Unavailable** Finds. It also skips an unchanged result checked within the last six days. Sanity revision conditions prevent concurrent runs from overwriting an intervening edit; a revision conflict is counted as skipped. The run checks at most 40 referenced Finds in groups of four to stay within the function limit; exceeding that cap fails safely and requires revisiting the batch size. It reports partial failures with HTTP 503. A missing referenced published Find counts as a failure. Draft-only Finds are never checked or written. If a published Find also has a draft, the monitoring values on its draft may remain older until that draft is published; editors should check the published record's status when reviewing a draft.

In Studio, open **Amazon Finds → Finds Needing Attention** to review flagged records. **Manually Unavailable Finds** lists editor-confirmed unavailable products. Open a Find's **Link monitoring** group to see the last result and time, and use **Used in Looks** above the form to navigate to each linked Look, including its publication status and Essential/Alternative placement. Confirm an item is unavailable yourself before choosing **Unavailable** and publishing the Find. That status hides the Amazon CTA on Look and Review pages; it does not remove the Find or Look. **Healthy** means URL integrity checks passed, not that the product is in stock.

[Amazon's Associates policies](https://affiliate-program.amazon.com/help/operating/policies) prohibit artificially generated clicks or sessions, so this checker deliberately avoids recurring requests to Amazon pages. [Vercel documents](https://vercel.com/docs/project-configuration/vercel-json#crons) the cron schedule configuration and its production-only execution. A future authorized product API may provide stronger availability evidence, but it is not included here. Monitor execution and errors in Vercel function logs after deployment. Do not configure a production token until the local implementation and permissions have been reviewed.
